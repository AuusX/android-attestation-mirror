# Android硬件证明资料签名镜像

服务器每10分钟向这个专用仓库提交一个公开的刷新请求，GitHub Actions随即从Google官方HTTPS端点获取公开根证书和撤销列表，生成签名快照。不依赖开发电脑或业务服务器的代理。

仓库只发布公共资料、原始HTTP时间和快照签名，不包含应用名单、用户数据、卡密、业务凭据或服务器私钥。镜像使用独立的Ed25519签名密钥，与APK签名及服务器授权票据密钥无关。

## 启用

1. 把本目录发布到自己控制的公开GitHub仓库，默认分支使用`main`。
2. 单独生成镜像签名密钥，把64字节私钥的Base64编码存为仓库Actions Secret：`ATTESTATION_MIRROR_SIGNING_KEY`。私钥不提交到Git；32字节公钥的Base64编码由服务器固定保存。
3. 手动运行一次“刷新公开的Android硬件证明资料”，确认成功产生`snapshot.json`。
4. 服务器配置自己控制的仓库和独立验签公钥，每10分钟调用`refresh-attestation-mirror.php`。先完成定时刷新和手机授权验证，再将证明模式切换为`required`。
5. 服务器使用仅对这个仓库生效的Deploy Key，定时更新`refresh-request.txt`。文件只包含UTC请求时间及随机标识。工作流只响应该请求文件，自己提交快照不会造成递归触发。

服务器镜像配置示例（放在网站公开目录之外）：

```json
{
  "repository": "自己的账号/仓库名",
  "public_key": "独立镜像验签公钥的Base64编码"
}
```

## 验证规则

服务器检查预置公钥签名、固定Google源地址、原始HTTP时间、证书结构与签名，并只采用服务器本地维护的应用允许列表。资料过旧、签名错误、下载失败或出现回退时保留上次策略；不会通过反复下载旧快照延长其有效期。策略最长1小时有效，过期后拒绝新的证明授权。

定时由服务器cron驱动；GitHub负责执行请求触发的任务。上线验收必须核对cron提交记录、对应GitHub `push`运行、签名快照摘要，以及服务器采纳结果。GitHub执行队列或网络故障仍可能延迟更新，因此保留策略到期拒绝和故障记录。

发布本仓库后，使用方仍需固定验签公钥、验证实际定时更新，并单独完成自己的硬件证明启用验收。
